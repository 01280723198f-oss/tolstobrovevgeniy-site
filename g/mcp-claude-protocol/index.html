MCP (Model Context Protocol) в Claude Code: полный гайд

Model Context Protocol (MCP) — это новый стандарт, как Claude напрямую подключается к твоей системе: БД, сервисам, приватным данным. Не через REST API обвязку. Прямо.

Что изменилось

До MCP (старый способ):

  1. Ты пишешь функцию, которая вызывает REST API
  2. Claude вызывает эту функцию
  3. Функция отправляет запрос в облако
  4. Ответ приходит назад
  5. Claude видит результат

Это работает, но:

  • Три слоя обвязки (функция → API → БД)
  • Каждый сервис — свой способ интеграции
  • Безопасность: тебе нужны API-ключи везде

После MCP (новый способ): Claude знает твою БД напрямую. Видит схему. Может писать SQL. Видит результат. Никакой промежуточной обвязки.

Как это работает технически

  1. MCP сервер — это программа на твоём компьютере или сервере, которая знает, как общаться с Claude
  2. Инструменты — что MCP сервер может делать (например, "выполнить SQL запрос")
  3. Claude видит инструменты и использует их, когда нужно

Пример:

Ты: "Сколько пользователей заказали за день?"

Claude видит инструмент "execute_sql"
Claude пишет: SELECT COUNT(*) FROM orders WHERE date > NOW() - INTERVAL 1 DAY
MCP сервер выполняет SQL
MCP возвращает: 1,243
Claude говорит: "За день заказало 1 243 пользователя"

Всё в одном процессе. Без API вызовов. Быстро.

Зачем это нужно

Скорость

REST API → сетевая задержка → ответ. MCP → выполнить локально → ответ моментально.

Безопасность

С REST API тебе нужны ключи везде. С MCP Claude работает через единую точку входа.

Единство

Вместо "пять разных способов интегрировать Notion, GitHub, Slack, Google Docs" — один стандарт MCP.

Масштабируемость

Claude может работать с несколькими MCP серверами одновременно.

Практические примеры

Пример 1: вся информация про клиента в одном запросе

Ты даёшь Claude имя клиента.
Claude через MCP:
  - Смотрит в БД (таблица clients)
  - Смотрит в GitHub (его репо)
  - Смотрит в Google Docs (его документы)
  - Смотрит в Slack (его сообщения в приватном канале)

На выходе: полный профиль, собранный из пяти источников.

Как начать с MCP

Шаг 1: выбери, с чем интегрироваться

Популярные варианты:

  • Собственная БД (PostgreSQL, MySQL)
  • GitHub (читать репо, issue, pull requests)
  • Notion (читать/писать в БД)
  • Google Docs (читать документы)
  • Slack (читать каналы, отправлять сообщения)

Шаг 2: найди MCP сервер или напиши свой

Готовые серверы:

  • mcp-postgres — для PostgreSQL
  • mcp-notion — для Notion
  • mcp-github — для GitHub

Шаг 3: подключи к Claude Code

Две строки в конфиг → Claude видит инструменты → готово.

Главное: это сдвиг от "Claude вызывает функции" к "Claude это часть твоей системы".

Частые ошибки при подключении

Слишком широкие права. MCP-сервер для БД по умолчанию видит все таблицы, включая те, куда лучше не пускать модель напрямую (платежи, персональные данные). Права нужно резать на уровне самой БД — отдельным пользователем с урезанными правами, а не надеяться, что Claude сам не полезет куда не надо.

Один сервер на все сервисы. Соблазн подключить сразу пять MCP-серверов и не думать о том, какой инструмент откуда. На практике Claude путает похожие инструменты (два "execute_query" от разных серверов), если их не разграничить по имени и описанию.

Забытый лимит на запись. MCP даёт Claude возможность не только читать, но и писать — включая DELETE и UPDATE. Без явного ограничения на уровне сервера («только SELECT») агент рано или поздно выполнит деструктивный запрос, если попросить его не совсем точно.

Частые вопросы

MCP заменяет обычный API?

Нет, он работает поверх твоей же системы — просто без обвязки в виде отдельного REST-эндпоинта для каждого действия. Внутри MCP-сервер обычно и так дёргает твою БД или API, только Claude не видит эту прослойку.

Нужно ли знать программирование, чтобы поставить MCP-сервер?

Готовые серверы (mcp-postgres, mcp-github, mcp-notion) ставятся конфигом — пару строк в настройках Claude Code, без кода. Свой сервер под нестандартный сервис уже требует написать несколько функций.

MCP работает только в Claude Code?

Протокол открытый, и его поддерживают и другие клиенты, но экосистема готовых серверов и документация сильнее всего именно вокруг Claude — там MCP обкатан дольше.

Чек-лист перед подключением боевого MCP-сервера

Перед тем как дать Claude доступ к рабочей БД или сервису, стоит пройтись по короткому списку, а не подключать по умолчанию:

  1. Отдельный пользователь с урезанными правами — не тот же логин, что использует продакшен-приложение
  2. Явный список разрешённых операций — если писать не нужно, права на запись не выдаются вообще, а не «выдаются и мы просто не просим писать»
  3. Логирование каждого запроса — чтобы при разборе странного результата было видно, какой именно SQL или вызов сделал Claude
  4. Тестовый прогон на копии данных — прежде чем подключать к боевой БД, стоит один раз прогнать типовые запросы на тестовой копии
  5. План на случай сбоя — что произойдёт, если MCP-сервер упадёт посреди рабочего дня: Claude должен сообщить об ошибке, а не тихо пропустить шаг

Это занимает час на старте и снимает большинство инцидентов, которые потом дорого разбирать постфактум.
