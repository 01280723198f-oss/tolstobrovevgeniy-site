Как это работает

Claude Code умеет собирать автоматизации сам. Ты описываешь процесс словами, как объяснил бы помощнику: откуда взять данные, что с ними сделать, куда отправить. Он пишет код связки и помогает запустить её по расписанию.

Внутри самого Claude Code тоже есть автоматизация. В официальной документации на русском есть раздел про hooks: это команды, которые запускаются сами на определённых событиях. Например, прислать уведомление, когда нужен твой ответ, или проверить файлы после правки.

Что я перенёс на свой код

Штук пять задач, за которые раньше платил бы сервисам или делал руками:

  • Хостинг сайта. Сайт-хаб переехал на бесплатный GitHub Pages, публикация новой статьи это одна команда
  • Автопостинг во ВКонтакте. Скрипт раскладывает посты в отложенные записи каждый день
  • Бот-подарок в Telegram. Выдаёт подарок за подписку, собирает базу и делает рассылки
  • Доставка контента. Готовые ролики и описания сами приходят мне в Telegram на проверку
  • Счётчик посещений. Свой простой счётчик для сайта в дополнение к Метрике

Сэкономил не только деньги. Главное, что автоматизация перестала быть чужой коробкой. Когда что-то ломается, я открываю файл со связкой и правлю. Не жду поддержку, не ищу обходной путь в настройках. Правка занимает минуты.

Как считать стоимость сервисов

У сервисов автоматизации разные модели оплаты, и от неё зависит, сколько ты заплатишь при росте.

Zapier считает задачи. На странице тарифов бесплатный план ограничен 100 задачами в месяц, дальше тариф растёт вместе с числом выполненных шагов. Чем длиннее цепочка и чем чаще она срабатывает, тем дороже.

n8n считает запуски. На их странице тарифов прямо сказано, что платишь за запуск сценария целиком, а не за каждый шаг внутри. Для длинных цепочек это заметно дешевле.

Прежде чем выбирать, посчитай: сколько раз в месяц срабатывает связка и сколько в ней шагов. Умножь и сравни с тарифами. Иногда разница в разы.

Где сервис всё ещё выгоднее своего кода

Свой код не всегда лучше. Я оставил бы сервис, если:

  • Связка нужна на пару недель. Писать и поддерживать своё дольше, чем заплатить месяц
  • Нужны десятки готовых интеграций. Сервис уже умеет ходить в сотни приложений, а свой код придётся учить каждому
  • Автоматизацией пользуется команда без технаря. Визуальный редактор понятнее, чем файл с кодом
  • Нет сервера или компьютера, который работает постоянно. Своей связке нужно где-то жить

Подробнее о том, какие цепочки из n8n сворачиваются в один скилл Claude, а где визуальная автоматизация выигрывает, писал в статье Один скилл вместо семи нод.

Как собрать первую связку

  1. Выбери одну рутинную цепочку, например «заявка из формы → таблица → уведомление в Telegram»
  2. Опиши её словами: откуда данные, что с ними сделать, куда отправить, что делать при ошибке
  3. Попроси Claude Code собрать связку и объяснить, как её запустить
  4. Проверь на тестовых данных, прежде чем пускать живые заявки
  5. Запиши, где лежит файл, чтобы через месяц не искать

Что делать, если связка сломалась

Свою автоматизацию ломают обычно одни и те же вещи: изменился формат данных, истёк ключ доступа, сервис на той стороне поменял правила. Порядок действий у меня такой:

  1. Открыть файл связки и лог ошибок, если он пишется
  2. Вставить ошибку в Claude Code и попросить объяснить, что случилось, простыми словами
  3. Попросить исправить и заодно добавить понятное сообщение, если это повторится
  4. Прогнать связку на тестовых данных и только потом вернуть в работу

Чаще всего вся починка занимает несколько минут. Это и есть главное отличие от чужого сервиса: ты не ждёшь ответа поддержки и не ищешь обходной путь, а правишь причину.

Полезная привычка: пусть каждая связка при ошибке присылает тебе короткое сообщение в Telegram. Тогда ты узнаёшь о поломке сразу, а не через неделю, когда заявки уже потерялись.

Можно ли заменить Zapier своим кодом?

Для простых повторяющихся цепочек да, и это обычно дешевле при росте. Для десятков разных интеграций сервис остаётся удобнее.

Что выгоднее, n8n или Zapier?

Зависит от длины цепочек. Zapier считает каждую задачу, n8n считает запуск целиком, поэтому для длинных сценариев n8n обычно выходит дешевле. Посчитай на своих цифрах.

Нужен ли сервер для своей автоматизации?

Для связок, которые должны работать круглосуточно, нужен компьютер или сервер, который постоянно включён. Для задач по расписанию раз в день хватит и своего компьютера.
