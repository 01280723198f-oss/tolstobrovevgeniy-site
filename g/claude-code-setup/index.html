Как подготовить Claude Code к любому проекту

Полная настройка с нуля: команды, файлы, скиллы и права. Те 20 минут, после которых Claude работает не на 10%, а на полную.

Ты установил Claude Code, открыл терминал, написал «сделай мне сайт» — и получил что-то среднее, безликое, не своё.

Дело не в Claude. Ты дал гениальному сотруднику задачу, не сказав ему ни слова о себе, продукте и клиентах.

Эта инструкция — про подготовку. Тут конкретные команды, примеры файлов и настройки, которые превращают «нейронку для болтовни» в сотрудника, который знает твой проект. Делай по порядку — займёт минут 20.

Принцип, который меняет всё: сила не в том, чтобы дать Claude хорошую задачу. Сила в том, чтобы СНАЧАЛА собрать ему контекст, а потом давать задачи.

Вот порядок прокачки, по нему и пойдём:

  1. Память и контекст проекта — кто ты, продукт, аудитория, голос.
  2. Скиллы — навыки под конкретные задачи (готовые + свои).
  3. Инструменты (MCP) — подключение внешних сервисов.
  4. Права и настройки — чтобы не дёргал по мелочи и работал быстро.

Шаг 1. Память и контекст — фундамент, без которого всё бессмысленно

Если пропустишь этот шаг — Claude будет угадывать. Всё остальное держится на нём.

Команды старта

Запусти Claude Code в папке проекта и дай ему собрать «паспорт проекта» автоматически:

Команда Что делает
claude запускает Claude Code в текущей папке
/init сам изучает проект и создаёт файл CLAUDE.md
/memory открыть и отредактировать файлы памяти

Что такое CLAUDE.md

CLAUDE.md — это «паспорт проекта». Claude читает его сам в начале каждой сессии. Лежит в корне проекта. После /init он уже создан — тебе остаётся допилить его под себя.

Вот скелет, который реально работает (заполни своим):

# Проект: [название]

## Что это
Канал/продукт про X. Этап: запуск с нуля. Цель: [к чему идём].

## Целевая аудитория
Кто: [портрет]. Боли: [1-2 главные]. Язык: [как говорят].

## Голос и правила
- Пишу так: [тон, примеры].
- НЕЛЬЗЯ: канцелярит, «в современном мире», симметричные списки.
- Стоп-слова: [твои].

## Что важно
- [приоритет 1]
- [приоритет 2]

💡 Не пиши роман. Пиши плотно — только то, чего Claude не угадает сам. Лучший лайфхак: попроси «изучи проект и помоги дописать CLAUDE.md» — он задаст вопросы и соберёт сам.

Три уровня памяти (важно)

  • ~/.claude/CLAUDE.md — глобальный, про тебя. Действует во всех проектах.
  • ./CLAUDE.md — проектный, лежит рядом с проектом. Главный для конкретной работы.
  • Постоянная память — факты, которые переживают перезапуск (ключевые решения, предпочтения). Один раз сказал — помнит всегда.

Шаг 2. Скиллы — навыки, которые качают Claude под задачи

Скилл — это упакованная инструкция + знания под конкретный тип работы. Условно «профессия», которую Claude подгружает САМ, когда задача ей соответствует: скилл под презентации, под PDF, под написание постов, под анализ данных.

Где они лежат

  • ~/.claude/skills/ — глобально, во всех проектах.
  • проект/.claude/skills/ — только в этом проекте.

Где брать готовые скиллы

  1. Официальные от Anthropic — репозиторий github.com/anthropics/skills. Навыки под документы (PDF, DOCX, XLSX, PPTX), оформление, код. Скачал → положил в папку скиллов.
  2. Плагины и маркетплейсы — команда /plugin прямо внутри Claude Code. Там готовые наборы от сообщества, ставятся в пару кликов.
  3. Сообщество на GitHub — ищи по claude code skills, claude skills. Перед установкой открой и прочитай — это просто текстовые инструкции, ничего волшебного.

Как собрать СВОЙ скилл (то, что отличает профи)

Свой скилл = твои знания, твой голос, твои правила, упакованные так, что Claude применяет их сам, без напоминаний.

В Claude Code есть скилл skill-creator — он соберёт новый скилл по шагам. Просто напиши задачу:

Помоги создать скилл для написания постов в моём стиле

Внутри скилла — файл SKILL.md с «шапкой» (frontmatter). Именно поле description решает, КОГДА Claude сам подхватит скилл:

---
name: мои-посты
description: Пишет посты в голосе автора для Telegram-канала про X.
  Используется, когда нужен пост, прогрев или контент-план.
---

# Инструкция
Тон: ... Правила: ... Чего нельзя: ...

Рядом кладёшь папку references/ — туда стиль, примеры, форматы, банк фраз.

💡 Первый скилл собирай под главную повторяющуюся задачу. Пишешь контент — скилл под голос. Делаешь сайты — под свой дизайн-стандарт.

Шаг 3. Инструменты (MCP) — руки во внешнем мире

По умолчанию Claude работает с твоими файлами и терминалом. MCP даёт ему доступ к внешним сервисам: дизайн-инструменты, базы знаний, браузер, твои данные.

Команда Что делает
claude mcp add <имя> подключить сервис
claude mcp list посмотреть подключённые
/mcp управление прямо внутри Claude

Не подключай всё подряд. Начни с того, что реально используешь, добавляй по мере роста задач.

Шаг 4. Права и настройки — чтобы не тормозил

По умолчанию Claude спрашивает разрешение на каждое действие. Это бесит и тормозит. Настрой список разрешённых команд один раз — в файле .claude/settings.json.

{
  "permissions": {
    "allow": ["Bash(npm run *)", "Bash(git *)", "Read", "Edit"],
    "ask":   ["Bash(rm *)"]
  },
  "model": "claude-opus-4-8"
}
  • allow — что разрешено без вопросов (быстрее работа).
  • ask — что всегда переспрашивать (опасное, типа удаления).

Ещё полезные команды настройки:

Команда Что делает
/config открыть настройки
/model сменить модель (Opus / Sonnet / Haiku)
/agents субагенты — помощники под крупные задачи
/help список всех команд

На старте не закапывайся. Сделай Шаги 1–2 как следует — этого уже хватит, чтобы почувствовать разницу.

Шпаргалка: что вводить и зачем

Команда Зачем
claude запустить в папке проекта
/init создать паспорт проекта CLAUDE.md
/memory редактировать память
/plugin маркетплейс готовых скиллов
/mcp подключённые инструменты
/config настройки и права
/model сменить модель
/help все команды

Чек-лист: ты готов, если

  • Создан CLAUDE.md с продуктом, аудиторией, голосом и целями
  • Включена постоянная память (помнит тебя между сессиями)
  • Установлен хотя бы один официальный скилл под твою задачу
  • Собран свой скилл под главную повторяющуюся работу
  • В settings.json настроены права (allow / ask)
  • Подключены нужные MCP-инструменты (если задача требует)

Поставил все галочки? У тебя больше не «нейронка для болтовни», а настроенный сотрудник, который знает проект и работает на полную.

Три ошибки настройки, которые стоят дороже всего

Файл памяти на десять страниц. Кажется, что чем больше сказано, тем лучше поймёт. На деле важное тонет среди второстепенного, а внимание тратится на всё сразу. Тридцать-пятьдесят строк работают лучше трёх страниц.

Противоречия внутри правил. В одном месте «пиши коротко», в другом «раскрывай подробно». Модель выбирает случайно, ты видишь нестабильность и винишь модель. Перечитывать правила целиком раз в пару недель — дешёвая привычка с большой отдачей.

Права даются раньше, чем сетка отката. Снимать подтверждения имеет смысл только тогда, когда любое действие откатывается одной командой. Иначе однажды придётся вручную вспоминать, что было в файле до правки.

Как понять, что настройка удалась

Проверка занимает пять минут и делается на настоящей задаче, а не на учебной.

Задай вопрос, ответ на который зависит от твоего проекта: кто аудитория, чем отличаемся от конкурентов, каким голосом говорим. Общий ответ означает, что контекста нет.

Дай задачу обычными словами, не называя навыков. Если нужный включился сам — описания написаны правильно.

Начни новую сессию и спроси про вчерашнее решение. Помнит — память работает. Не помнит — журнал не пополняется.

Три проверки закрывают вопрос, работает ли настройка или ты просто создал файлы.

Частые вопросы

Сколько времени занимает настройка Claude Code?

Базовая — около двадцати минут: файл памяти проекта, два-три навыка, нужные коннекторы и права. Дальше система дописывается по ходу работы, отдельного этапа настройки не требуется.

Что писать в файл памяти проекта?

Кто ты, чем занимаешься, кто аудитория, каким голосом говоришь, как с тобой работать и где брать данные. Плюс запреты — например, не выдумывать цифры, а ставить пропуск.

Обязательно ли подключать коннекторы?

Нет, начать можно без них. Они нужны, когда ты замечаешь, что второй раз подряд копируешь данные из сервиса в чат руками: именно эта копипаста и есть недостающий коннектор.

Можно ли дать полный доступ без подтверждений?

Можно, но только после того, как собрана сетка отката: проект под контролем версий и бэкап уезжает сам. Полный доступ — это вопрос отката, а не смелости.

Главная мысль

Разница между теми, кто получает от Claude среднее, и теми, у кого он печатает результат как машина, — не в промптах. В подготовке.

Двадцать минут настройки экономят месяцы. С этого начинается любой проект, который ты выводишь на ИИ.
