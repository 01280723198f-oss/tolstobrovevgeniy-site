Карусель тизерила приём: где визуальная автоматизация в n8n — это уже привычка, а не необходимость. Здесь — расшифровка, какие задачи реально закрываются одним скиллом, а где n8n всё ещё нужен.

Откуда взялась привычка «рисовать ноды»

В 2023–2024 я сам жил в n8n и Make. Это была революция: вместо кода — визуальные блоки, между ними стрелки, и оно работает. Можно было «автоматизировать» что угодно за вечер.

Но у визуальных схем была обратная сторона. Чем больше ты строил — тем больше у тебя становилось точек, в которых что-то могло порваться. Webhook прислал не то, API сменил формат, лимит закончился. Половина времени уходила не на работу, а на починку.

И в этот момент пришёл LLM, который умеет делать всё то же самое внутри одного запроса. И многие схемы из «рисуем ноды» превратились в «один промпт + один скилл».

Что закрывает один скилл в Claude

  • Парсинг + чистка + выгрузка. Раньше: HTTP-нода → Code-нода для regex → Set-нода → Sheets-нода. Сейчас: один скилл, который принимает URL/файл, парсит, чистит и пишет в нужный формат.
  • Сортировка входящих сообщений. Раньше: webhook → switch-нода с правилами → ветки. Сейчас: скилл, который классифицирует по смыслу, а не по ключевым словам.
  • Генерация и рассылка контента по шаблону. Раньше: триггер по расписанию → шаблон → отправка. Сейчас: один скилл, который сам понимает контекст недели и собирает сообщения под него.
  • Поиск, агрегация, ресайз. Любая цепочка из 4–7 нод, где между блоками только перекладывание данных, сворачивается в один промпт.

Общее правило простое: если между нодами в основном «перенеси значение из A в B и поменяй формат» — это уже LLM-задача.

Где n8n всё ещё лучше

Честно: не везде один скилл побеждает.

  • Стабильные расписания и cron'ы. Если задача — «раз в час дёрнуть API и записать в базу» — n8n или нативный cron надёжнее. Скилл — это всё-таки запрос, а не сервис.
  • Низкоуровневые интеграции, где важна каждая миллисекунда. Биржевые боты, мониторинг ставок, оптимизация задержки — LLM-обёртка лишняя.
  • Сложные ветвистые сценарии с долгим состоянием. Если у тебя 30 шагов и каждый меняет состояние большой сделки — визуальная карта в n8n всё ещё нагляднее.

Так что выбирай по принципу: где задача — «подумать и сделать», там скилл. Где задача — «дёрнуть и записать без раздумий, постоянно», там n8n или нативные тулзы.

Что выиграешь, когда переедешь

  • Меньше подписок на отдельные SaaS-сервисы.
  • Меньше «починки скотча» и ручного дебага.
  • Сценарии живут в коде/тексте — их можно версионировать в git, переносить между проектами, шарить.
  • Один и тот же навык работает на десятке проектов: «парсер тендеров» один раз написан — подключается куда угодно.
